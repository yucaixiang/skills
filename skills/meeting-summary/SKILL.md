# meeting-summary · AI 自动总结会议 / 群讨论

> 让会议从"开完就忘"升级为"AI 提炼 → 文档归档 → 自动追踪待办"。

---

## When to Activate

- 用户说"总结 xx 会议"、"整理今天群里的讨论"
- 用户说"出一份会议纪要"
- 视频会议结束后
- 飞书群里激烈讨论后

---

## 4 段式纪要结构

```
1. 议题（Topic）       这次会议讨论了什么？
2. 讨论（Discussion）  各方观点和分歧
3. 结论（Conclusion）  达成的共识
4. 待办（Action）      谁、做什么、什么时候做完
```

```markdown

2. 与现有交易引擎的集成方案
3. 上线节奏与灰度策略

## 3. 讨论（按议题）

### 议题 1：限价单新功能需求评审

@产品-王：提出需求背景，目标本季度上线。
@张三（研发）：技术可行性 OK，但需评估性能影响。

  - @张三：本季度还有 P1 故障复盘要做。

### 议题 2：与现有交易引擎的集成方案

讨论了 3 个方案：
  A. 直接改 BonusCalculator（侵入大）
  B. 新增策略类（推荐 ⭐）
  C. 单独服务（过度设计）

### 议题 3：上线节奏

讨论了灰度策略：5% → 50% → 100%

✅ 决定 1：采用方案 B（新增策略类，不动现有 Calculator）
✅ 决定 2：本季度必须上线，研发投入 4 人/2 周
✅ 决定 3：灰度按"代理账号哈希"分组，5% → 50% → 100%

## 5. 待办

| # | 待办 | 负责人 | 截止时间 | 优先级 |
|---|---|---|---|---|

| 3 | 测试用例设计 | @李四 | 2026-06-05 | P0 |
| 4 | 评审会议安排 | @张三 | 2026-06-06 | P0 |
| 5 | 灰度脚本准备 | @SRE | 2026-06-10 | P1 |
| 6 | 监控告警配置 | @SRE | 2026-06-12 | P1 |
```

## AI 提炼的关键原则

### ✅ 必做

- **保留具体决定**："决定 1：采用方案 B" 比 "讨论了几个方案" 强 100 倍
- **保留分歧**：让没参会的人知道哪里有过争议
- **量化待办**：每个待办必须有负责人 + 截止时间
- **去除冗余**：忽略寒暄、跑题、口头禅

### ❌ 不做

- 不写"大家讨论了 xxx"（说了等于没说）
- 不堆原话（要提炼）
- 不带个人评价（"@张三 说得有道理"）
- 不超过 1 页

## 进阶玩法

### 1 · 视频会议自动总结

```
"总结今天上午 9 点产品评审会"
```

AI 调 `lark-cli/lark-minutes` 拉视频纪要，自动总结。

### 2 · 长期讨论汇总

```
"过去一周 #限价单需求群 的所有讨论，按议题汇总"
```

按议题分类，输出累积演化。

### 3 · 跨群讨论汇总

```
"汇总 #产品组 #研发组 关于 xx 的所有讨论"
```

跨群提炼共性问题与分歧。

## 反例

| 反例 | 改正 |
|---|---|
| 纪要 = 聊天记录全文 | 必须提炼 |
| 没有待办 | 必须列出 |
| 待办没责任人 | 必须 @ 人 |
| 没共识只有讨论 | 必须给出"决定了什么" |
| 总结后不归档 | 必须同步飞书 |
| 不通知相关人 | 必须 @ all |
